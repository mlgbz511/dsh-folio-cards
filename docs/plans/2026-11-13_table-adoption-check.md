# table 块的采纳率验收（rompt 硬化后）

目的：验证 GUIDE 的硬判据是否真的让模型主动写 `table`，而不是继续用 bullets 罗列对照数据。

## 判据

- 达标线：**≥ 80%**（15 次里至少 12 次出现 `table` 块）
- 未达标：先看失败样本是「写成 bullets」还是「写成 kv」，再决定补示例还是上客户端自动升级（`paragraph` 内 markdown 管道表转 table）

## 五条固定提示 × 各 3 次

1. 三种部署方式的上下文、首字延迟、关键策略对比
2. 四个方案的月费、并发上限、SLA 对比
3. 中国、印度、美国三国的人口、面积、人均 GDP 对比
4. v1 与 v2 两个版本的 API 差异（端点、鉴权、限流）
5. Python、Rust、Go 在启动速度、内存占用、生态成熟度上的对比

## 记录方式

| 提示 | 第 1 次 | 第 2 次 | 第 3 次 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |
| 4 | | | | |
| 5 | | | | |

填 `table` / `bullets` / `kv` / `无卡`。空着就说明该轮没写卡片。

## 注意

- 每次测试前确认 App 已重启（宿主提示词在启动时组装）。
- 对照数据不超过 2 个对象、2 个字段时，正确的行为是 `kv`，不算失败。
- 若稳定 80% 以上，不要提前加自动升级逻辑 —— 那是给未达标准备的兜底，不是默认路径。
